## 旧方案的问题

原 5i0b/molecule_000/t=0.5 API 方案把局部 C4–C12 键长异常和全分子 MMFF 应变代理同时出现，解释成该键导致全分子应变。生物计划的修复判据同时要求键长落入区间、整体应变低于筛查阈值，数学表达式却只有一个距离残差。局部键长下降并不能证明联合判据成立；高位移的应变定位也不是能量项分解。

旧奖励的 1.3221–1.6159 Å 来自 `1.469 × (1 ± 0.10)`。1.469 Å 是当前离散图假设下的 MMFF 参数参考，10% 是诊断筛查阈值。这能描述筛查窗口，但没有提供容差的实验或统计标定，不能自动成为物理可接受集。

该奖励检索了 P01 的完整 MMFF 能量分解，却用 flat-bottom 距离代理替换它。已有源码校验能证明引用来自实际检索，不能证明数学形状保留了引用的物理含义。双专家实际走 MarkdownCorpus；旧规划器的 G01 额外加分不是这次选择的直接原因。

另一个调用链缺口是：运行时虽然读取了创造性奖励 Skill 与 core-target/shape 指引，但原双专家分支没有把它们传入专家的系统指引。现已将实际宿主 Skill 传入两个专家，并对最终有效指引分别记录摘要哈希，避免出现“配置已加载，模型却未看到”的情况。

## GLM 调用配置

使用 OpenRouter 的 OpenAI 兼容 Chat Completions 接口，仍由 LangChain 调用。保留原生 OpenRouter SDK 选项，旧配置继续可用。默认配置明确选择：

- 所有角色使用 `model=z-ai/glm-5.3`、`reasoning_effort=low`；数学专家使用独立流式配置；
- 默认输出预算 32768 token，数学专家单次预算 16384 token，请求超时 300 秒；
- 要求服务端支持请求参数，工具调用不并行；
- 最多 24 轮 Agent 调用、8 次有界修复。

GLM-5.3 的推理始终启用，支持 low/high/max，默认 max；不能把 `enabled=false` 当成可靠的关闭办法。推理 token 通常计入输出预算，输出上限必须给最终工具参数留余量。前十一轮中，low 配置虽完成真实请求，数学专家仍反复违反长契约的来源、参数与表达式要求，未完成 Executor 提交，因此第十二至十四轮试用了 high/49152。但大请求连续约 304 秒后丢失流终止信号，未完成数学提交。最终配置回到 low/16384，结合强制分段草案减少单次负担；所有检查保持完整。这是同一 GLM 模型的预算调整。

兼容适配器绕开额外生成的响应 schema，减少供应商扩展字段造成的解析故障。多轮需要的 `reasoning_details` 只在内存中原样传递，不进入实验审计。对截断回复或损坏的工具参数，整条回复的调用均不执行，并要求完整重发。不会切换其他模型或用离线方案假装 API 成功。

第十二轮 high 数学请求出现两次约 303 秒的非流式响应 JSON 解码失败，两次均是 1100 字符、错误位置位于正文末尾；这指向长请求的传输/超时问题，但仅凭这些收据不能断言是 GLM 模型本身或哪一层网关造成。数学配置现使用流式接收，保留 token 使用统计和服务模型；全部工具参数按索引拼接，只有流结束信号和原始参数字符串严格 JSON 解析都通过才允许执行。LangChain 的流式部分 JSON 自动补齐不能授权工具。同步和异步路径都拒绝缺少结束信号的流。推理增量只在临时内存中保留顺序，审计显式脱敏这些字段。

第十三轮流式请求连续完成五次数学工具调用，后续大回复在约 304 秒后结束但没有终止信号，适配器拒绝执行。GLM 的模型页列出 1M 上下文，不能把这次故障归因为 128k 上下文上限。调用收据显示生物物理工具回复使数学输入增加约 6.2 万 token；测量发现同一 metric 的观测值与引用 summary/rows 被重复发送。现将默认观测数组限制为带计数的四项预览，引用目录只发送元数据，增加可分页、按 atom_id 筛选的引用读取；原始证据与其内容哈希不变。旧 5i0b packet 上该工具 JSON 从 162715 字符降至 86662 字符。默认 evidence 的嵌套数组也同时有界化，避免另一个潜在输出膨胀入口。

参考：[OpenRouter 工具流式调用规范](https://openrouter.ai/docs/guides/features/tool-calling)、[推理块在流式与多轮请求中的结构](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)。这些传输规范不证明奖励的科学适用性，后者仍由契约和数值测试独立检查。

真实测试发现，阻塞条件的笼统反馈会导致模型重复相同字段错误。因此补充了 active factor 的字段说明和具体纠错提示，要求拆分不可实现的物理声明，保留其科学缺口；未来 GPU 验证不会被冒充为当前通过。另对完整响应 JSON 解码失败仅重试同一会话一次，记录位置、长度、错误类型与耗时，不保存响应正文。工具执行仍只接受完整解析并校验的消息。

数学专家通过测试后可以无参数提交主机保留的同一份方案，避免重新生成整段大型 JSON。主机只保存实际通过测试的版本，修改后的方案必须重新测试。

对于已提出但未通过的草案，新增 `patch_and_test_mathematical_design`：模型可以按 JSON 字段路径替换 1–16 个既有字段，主机在副本上合并并重新执行全部契约、来源、形状与数值测试。只有通过的版本才能提交。这不是自动修正模型的科学结论，也不绕过测试；它避免每次修复一个运算符或引用都重新输出完整方案。

多方向方案使用 `stage_mathematical_direction` 逐个保留模型提出的方向草案，再以 `test_staged_mathematical_design` 提交模型选择的策略、冲突分析、独立评价和架构审计。多方向时不向模型暴露一次提出完整草案的工具；单方向与旧路径仍可使用该工具。宿主只按生物计划顺序组装不变的方向，要求全部已选方向存在，再调用原有完整验证路径。`draft_only` 不表示契约或科学验证通过，也不能直接提交/执行；组装后的具体错误仍可局部修订。这降低单次大 JSON 回复的负担，不代替模型的数学选择。

表达式原来是普通字典，工具 schema 不能直接说明每个节点的单位、字段和参数数量。现改为递归的判别联合：观测量、常数、一元运算、power、二元运算和 sum/mean 归约各有明确字段；maximum/minimum 只能有两个参数。模型直接看到该 schema，宿主仍保留原始失败草案用于局部修订，并在执行前完整验证。错误路径去掉仅用于 Pydantic 分支的标签，指向可实际替换的 JSON 节点。旧表达式中的整数/浮点类型保持原样，避免破坏历史奖励内容摘要。

第八轮定位到工具框架重建 `SkipValidation` 子模型时丢失递归定义，尚未发起数学 API 就发生 KeyError。测试草案工具改为根部含完整定义的 JSON schema，工具体再执行全部 Pydantic、科学契约和数值校验。第九轮直接向供应商发送引用式 schema 后，连续得到 JSON 转义字符串形式的生物计划，严格验证拒绝了这些参数。因此供应商接口使用展开的普通字段和有界表达式预览，避免未解析引用与重复展开；完整递归 schema 由 `get_expert_contract` 提供，主机验证保持完整。供应商预览不是替代严格验证的规则。

第十轮还暴露了过于严格的来源文本匹配：LaTeX 公式加号两侧空格不同，被逐字符规则反复拒绝。现仅在 `$...$` 数学片段内忽略排版空白，公式 token、变量、系数、运算符及外部文字仍需匹配实际检索来源；原始记录不被改写。这是引用格式兼容，并不接受模型把另一种公式称为相同来源。

第五轮出现过逐条读取 19 个测量、耗尽 24 轮工具预算的失败。现支持一次批量读取 1–32 条引用；正常短数组保留原列表，只有长数组返回带计数的截断预览，完整摘要需要显式读取。未知引用错误定位到具体列表元素，临近工具预算上限时提示完成有依据的提交。这减少修复中的重复检索，不改变证据绑定或验证标准。

专家默认报告上下文也使用带截断标记的数组预览；数学契约不再重复发送完整受体坐标，只列受体数量、化学准备状态和精确绑定规则。原始数据仍完整保留在 StatePacket/Executor，精确测量按需读取。新增 `inspect_direction_functions` 一次检索同一方向的 1–12 个实际函数候选，返回各自真实检索和来源 ID，降低比较候选的调用轮次。

参考：[GLM-5.3 官方模型说明](https://openrouter.ai/z-ai/glm-5.3)、[推理预算说明](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)、[服务路线参数要求](https://openrouter.ai/docs/guides/routing/provider-selection)。

## 生物专家：先检查多因素，再决定哪些需要控制

新增强制 `factor_assessment`，覆盖八类因素：

| 因素 | 独立检查内容 | 不能由单距离自动证明的结论 |
|---|---|---|
| 键几何 | 当前键型、MMFF 局部参数和键长 | 键型、元素或质子化一定正确 |
| 键角、扭转、立体化学 | 周边角度、环/双键平面和手性参照 | 全构象合理或手性保留 |
| 分子内稳定性 | 能量、应变代理、分子内位阻与适用性 | 某一异常键是总应变的根因 |
| 空间可行性 | 口袋与分子内碰撞、连通性和价态 | 没有碰撞等于有好结合 |
| 靶点接触 | 配对对象、接触类型、方向和准备状态 | 最近原子对等于正确相互作用 |
| 接触面积与埋藏 | SASA/埋藏面积、指定基团与目标 | 面积越大越好或测量已有可微路径 |
| 化学身份与基团 | 元素/电荷/键类别不确定性、候选功能角色 | 坐标移动等于直接诱导元素或基团 |
| 终态任务效用 | 亲和力代理、QED/SA 与独立评价 | 诊断可读值等于可执行奖励梯度 |

每项必须说明证据、缺失条件、相关方向、优化/约束/监测/暂缓的处理和一个反例检查。调用上下文工具可看到原来没有进入风险清单的接触、埋藏、构象与终态测量。没有告警不等于最优；没有靶点/基团参照不允许编造目标。

旧契约要求每个方向都依附诊断 finding，正常测量无法独立成为保持项。现允许 `finding_ids=[]` 的独立任务/保持方向，并为原有正常测量提供 `me_` 引用，绑定 packet、view、metric、原始行路径与值的内容哈希。引用不修改 StatePacket、不制造风险告警；正常接触的原子/残基对可进入 receptor_distance 控制，缺少局部支持的汇总值不能授权任意原子梯度。对已测得的手性中心，按固定邻居顺序从原坐标计算带符号三重积，记录坐标哈希、四个原子 ID、体积和推导式，支持当前几何的手性保持；它不代表用户提供了目标 R/S 构型。方向必须说明任务需要；全部已有 finding 仍必须被处理，任意证据 ID 仍会被拒绝。

这不是强制八项相加。相关告警应合并成机制，优化项由独立任务需要决定；不可交易的性质需要真实约束，缺少质子化、部分电荷、SASA 导数或类别控制路径时保留暂缓项。

## 数学专家：函数库 → 适用性 → 形状 → 数值校验

1. 先看全部 21 个知识函数的目录、作用角色和前置条件，再按 function_id 精确检索原式。完整来源、行号、摘要和哈希进入检索记录。
2. 为方向建立 function_basis，比较直接修复、互补物理、保持机制、终态效用或离散算子的有关候选，保留选用、拒绝、暂缓的理由。
3. 区分保留原式、特化、另建代理。距离代理不能在未声明替换的情况下被称为完整 MMFF 能量；选用的函数必须进入实际公式谱系。
4. 为表达式每个常数填写精确匹配的来源记录：参考值、容差、归一化、物理系数或数学参数。观测参考必须在引用的证据中实际出现；来源定位符必须是实际检索 ID，不能用自造的 packet/biology 路径替代。没有进入表达式的观测值不能充当参数记录。筛查阈值或未标定假设仅允许 `bounded_hypothesis_pilot`，不能声明 `calibrated_repair`。
5. 给出目标集合、函数形状、活跃范围和导数响应。主机直接执行至少三组不同的 shape_probes，验证修复处的零值、违反处的非零值与每个保留观测量的导数符号。形状检查不替代真实生成器的 Jacobian 预检。
6. 检查生物因素及每个修复条款的实现覆盖。生物方向用 `repair_clauses` 列举每个条件，数学方向用 `predicate_coverage` 逐条绑定真实的观测量类型和证据。仅有 distance 的程序不能声称实现全分子稳定性、全接触网络或面积优化。未实现的全碰撞筛查、接触数量/比例、SASA、类别或终态 oracle 条款会阻止执行；必须请求生物修订或保留 design_only。
7. 比较架构并选一个明确的执行范围。单一目标仍可以用有依据的局部势；多个不可补偿条件必须保留其约束语义，不能靠添加固定权重制造科学合理性。

对于当前预测化学图假设下的参考，新增 `suspend_on_graph_change`。执行器发现预测离散图不再符合绑定假设时暂停额外引导，原生续采样继续。这是已编译奖励的适用性检查，不启动 MolMonitor 或图复核 API。旧奖励保持原有行为，便于历史实验复现。

第四轮真实调用还暴露了一种实际错误：数学草案把接触数、接触比例和埋藏比例写成“host post-step checks”，而执行器并未安装这些门禁。新增条款覆盖契约后，不能用两个 receptor_distance 观测量替代全部条件，也不能靠声明宿主检查通过验证。已有在线严重碰撞/信赖域防护与独立终态复评各有范围，不等于坐标副本测试已执行这些全局判据。

同时对实际出现的“no new … clashes”和命名的接触数量/比例、埋藏比例声明进行保守检查：这些全局条件必须有对应的正式条款，不能隐藏在局部距离条件的说明中。该检查不能证明任意自然语言与公式完全等价；最终的已执行范围以条款和表达式为准。

第十五轮完成了 23 次真实 GLM 请求与 Executor 数值提交，事后复核发现数学 `acceptable_set` 另加“独立 monitors 必须无回退才接受”，这些条件并未成为执行器门禁。因此保留原有数值运行记录，但新增事后复核不通过记录；该轮不作为最终科学验收。现同时检查数学可接受集，拒绝这一类隐含条件，要求尚未执行的独立评价移入 `independent_evaluation` 并标记 `not_run`。生物因素中的 monitor 标签也不意味着 MolMonitor 已运行。

该轮还发现某些服务端流重复发送终止元数据，LangChain 合并字符串后记录了重复的模型名及 `tool_callstool_calls`。适配器现收集并在流结束时仅发送一次 model/finish 元数据；任意长度截断信号保持优先，避免 `lengthlength` 逃过整体截断拒绝。同步与异步的重复终止测试覆盖此问题。

## 验证方法

数值与契约测试覆盖：遗漏因素、用距离冒充全局应变、未标定阈值冒充标定修复、伪造观测参考、表达式导数与摘要不符、遗留 handoff 兼容性、服务响应扩展与推理块连续性。真实 API 和采样结果单独记录在实验输出中；未完成的运行不得标为通过。

GPU 全流程入口是 `scripts/test_glm53_expert_design.py`，默认复制旧 test 的核验输入到新的 test 目录，保持 `data` 只读，并以 MolMonitor/图复核关闭运行五个权重。实例暂时缺少 GPU 时，`scripts/test_glm53_saved_state_api.py` 可对原已验证的 t=0.5 StatePacket 执行真实 GLM Reader、双专家和 Executor 数值验证；该阶段明确将当前 live derivative、续采样和五档实验记录为 `not_run`，不能替代 GPU 实验。数学方向的 `executable` 仅描述当前表达式及坐标副本求值，未来在线验证单独列出；真实缺失的力场、受体或几何输入仍阻止执行，不能通过清空字段消除科学缺口。

来源绑定、维度与形状检查能阻止若干具体错误，但不能自动证明生物因果关系或完成物理容差标定。完整物理能量、SASA、类别控制和结合效用仍需要各自输入、执行路径及独立验证；字段齐全不等于优化一定有效。

## 前次模型切换、有效引导步与 MolMonitor

前次切换至 Qwen 的直接原因是 GLM 运行未通过工具契约，耗尽修复预算。保存的 `run_02` 中 GLM 完成了 29 次请求，研究和数学工具仍未产生可提交方案；这表明是流程未完成，不能据此断言 GLM 的科学能力较弱。切换模型完成了前次 Qwen 实验，却没有解决原 GLM 调用链。此次保留 GLM，针对实际问题修复 schema、约束含义、证据绑定、错误反馈和草案修订接口，失败轮次完整保存。

前次五档实验每档都续采样 50 步，但“有梯度”“被接受”和“非零有效位移”不同：

| 权重 | 有梯度步 | 接受步 | 非零有效位移步 | 零梯度步 | 被接受但零位移 |
|---:|---:|---:|---:|---:|---:|
| 1 | 42 | 40 | 40 | 8 | 0 |
| 10 | 42 | 42 | 42 | 8 | 0 |
| 100 | 28 | 28 | 28 | 22 | 0 |
| 300 | 28 | 28 | 26 | 22 | 2 |
| 500 | 28 | 28 | 25 | 22 | 3 |

因此“25–40 步”漏掉了权重 10 的 42 步，结果也不是随权重严格递减。区间内 flat-bottom 势为零，t≈0.75–0.82 的八步无梯度；大权重分支后段另外十四步处于零梯度区域。权重 1 有两步提议在同一时刻预测检查中仍出现奖励回退，被拒绝。高权重更快耗尽累计 0.5 Å 路径预算，单步上限为 0.02 Å，权重 300/500 另有两/三步接受了零位移提议。零梯度与预算耗尽需要分别统计，不能统称 Monitor 降权。

这五档中 MolMonitor 未执行任何控制，图复核次数均为零；五档权重固定，奖励没有在线重写。裁剪、回溯、约束检查与路径预算属于 Executor。生物方案里的 `monitor` 是方向处理标签，不等于启动 MolMonitor。旧实验中离散化学图由 C 假设转为 I/F 后，原窗口仍可计算但化学解释失效；新图适用性暂停策略专门限制这个问题。

Executor 数值测试复用 `molmonitor/checks.py` 的有限差分检查函数；调用这个库函数不表示运行 MolMonitor Agent 或监控/降权循环。

如果启用 MolMonitor，它按每项指标的滑动中位数/MAD 监控偏离，经过预热、持续异常和冷却判定后，先降低执行强度，有限次调节后请求 Thinker 重设计；健康数据用于恢复强度，异常不进入基线，非有限指标停止运行。可选图复核位于 `molmonitor/graph_review`，默认关闭；开启后由 Monitor 分派图变化事件给 Reader 和 Thinker。实际开启时控制的是执行强度/路由，不能把它解释为自动求得科学合理的奖励常数。
