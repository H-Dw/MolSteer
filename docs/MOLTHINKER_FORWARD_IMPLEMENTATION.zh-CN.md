# MolThinker 生成中间态前向流程：实施说明

2026-10-01。本轮按[规划](MOLTHINKER_INTERMEDIATE_STATE_PLAN.zh-CN.md)修改实际双专家流程。科学目标和函数由 Agent 根据当前状态决定；没有固定目标数、收益分数、容差、聚合式或权重写入 skills。最终 `skills/` 相对于上次提交没有变动，撤回了上一轮尚未提交的反事实排序和特定工具说明。

## 实际改动

生物专家收到当前时刻的状态表示、当步预测、诊断和可用性。`inspect_biophysical_context` 默认分开返回 `state` 与 `prediction`，可以按表示单独读取；额外 SDF 等视图仅报告可用性，避免误混入生成状态或错误绑定。预测被明确标记为当步估计，不能当作未来实测终态。

`decision_workspace.py` 提供机制整合、候选目标和选择的公开草稿。潜在收益按直接修复、独立问题覆盖、局部可行性、控制范围与耦合风险说明，不计算终态收益差或成功概率。覆盖辅助只检查 Agent 声明的机制集合与删除后的缺口；资料不全返回未知，不自动决定因果关系、删目标、排名或权重。

`goal_pools` 分开科学目标、保留目标、可研究方向和编译候选。已有 `required` 与 `disposition` 表达科学选择：必要但无法执行的目标使用 `required=true, deferred`，仍进入数学阶段。研究入口可检索其他已登记的背景方向，研究本身不激活它们。数学交接和草稿组装保留必要的未实现目标，最终编译继续禁止把未解决目标当成可执行奖励。

数学专家先按机制检索，识别原始变量、作用对象、角色和前提，判断保留、特化或重构，再确定数学目标集合、参照与尺度，推导局部响应，构造与比较候选。`prepare_function_synthesis` 支持机制查询，不要求先选某个公式 ID。实际来源卡提供原公式及相关序列化选项；这些选项不决定目标或参数。

`record_function_derivation` 保存可增量修改的来源迁移、目标集合、局部响应和候选摘要。已有构造工具继续处理 AST、来源 locator、常量记录和导数示例；自定义表达式入口保留。未实现的评价器或控制器可以保留为 `design_only`，不必先替换成距离代理才能提交设计。通过检查的 deferred 草稿可以直接提交，同样不会获得数值通过或执行授权。

`workflow_guidance.py` 从配置的 Skill 目录加载真实 Markdown 引用。生物初始输入获得 grounding 段落，数学获得函数基来源段落；其余内容通过参考目录与受限读取工具按需取得。模型不再同时接收整份重复的两阶段材料。提示词摘要、所用参考来源摘要和公开工作区进入 checkpoint；供应商私有推理仍不保存。

没有新增强制工作区字段、阶段调用顺序 gate 或概率评分 gate。缺少辅助记录不阻断原有完成路径。表达式绑定、单位、有限性、最终数值测试及执行条件仍由既有契约负责。

## 验证与边界

新增行为验证覆盖：独立缺陷需要分别覆盖、同机制候选不重复打分、缺失覆盖信息保持未知、两种表示分离、未实现必要目标进入数学并保留、未选背景目标可以研究而不变成奖励，以及部分工作区的脱敏和实际参考资料交付。旧测试中的“读取整个 Skill”预期改为按角色读取；相同指标在不同表示中的测试显式绑定其视图。

全量回归 **336 项通过，0 失败、0 错误**，结果和本轮真实 API 状态记录在[验证记录](../validation/forward_decision_20261001.json)。脚本模型测试只证明输入/工具/交接行为；真实 GLM-5.3 的公开决策质量、实时生成器拉回以及五档续采样收益应分别验证，不从软件回归结果推断。

服务器测试副本上的本轮真实 GLM-5.3 调用完成了 4 次 MolReader 请求、3 次生物专家请求。生物提交包含局部键几何修复、全局 MMFF 应变目标、独立位阻保留和身份不确定性；没有调用可选工作区。第一次生物提交有一次既有证据绑定错误，修订后接受。数学专家第一个请求返回 HTTP 402，未产生数学设计，未运行新五档续采样，不能报告完整新流程通过。MolMonitor 与图复核关闭；原始 data 的 404 个文件和已有测试源副本完整性检查通过。

这份生物产物仍有质量边界：它用松弛位移区域不同支持“两个独立机制”，但位移分布不是能量分解，不能据此证明机制独立或最小充分性。数学来源迁移、目标集合和响应构造在真实模型上的质量仍未验证。这些结论作为实验反馈记录，不增加线上拒绝 gate。

保存状态 API 脚本增加 `--allow-design-only` 用于研究流程验证：它可以记录真实 API 产生的未解决科学设计，结果明确为 `design_deferred`；默认仍要求可执行奖励验证。该选项不会改变 Agent 的编译限制，也不把延期结果标记为优化成功。
